# 拆脚手架 + 交付质量门

> **这是最关键、也最容易被跳过的一步**。实战教训：某本书的初版留了 112 个 `<!-- v2 新增 -->` 标记 + 8 个自检清单 + 8 个版本记录，审计后发现"AI 老师没法做对比"，两轮清理共删除 36,477 字符（-9.4%）。**这不是可选项，是交付前的硬门。**

## 为什么必须拆（Phase 8）

**造书过程产生的所有元数据，对 AI 老师零价值。**

AI 老师只读最终这一本书。它没有 v1、没有"教师用书"、没有别的参照——所以书里任何"对比参照""修订日志""质检清单"都是噪音。

**口诀：拆完脚手架，书里只剩"教什么 + 怎么教"，没有"怎么造的"。**

## 必须拆除的 8 类过程元数据

| 类别 | 示例 | 为什么拆 |
|---|---|---|
| ① 版本标记注释 | `<!-- v2 师生合版新增 -->` | AI 老师看不到"v1"，标记无对照意义 |
| ② "新增内容"措辞 | "本单元新增了 X""v2 追加 Y" | AI 老师没有"旧版"可对比 |
| ③ 自检清单 | `- [x] 🎬 场景具体（…）` | 这是造书者的 QA 打勾，不是教学内容 |
| ④ 版本记录 | `v1.0（初稿）：完成 7 板块…` | 修订日志是作者维护笔记 |
| ⑤ 源教材引用 | "教师用书说…""教材原文指出…" | 转成"本单元…"直接陈述，不暴露来源 |
| ⑥ 造书者口吻 | "给人类教师读的""可追溯" | 转成"给 AI 老师的指令"语气 |
| ⑦ 增量描述 | "v2.0 增量""在 v1 基础上追加" | 删掉版本相对性，只留绝对内容 |
| ⑧ 过程勾选项 | 自检清单里的 `- [x]` 打勾项 | 全删 |

## Phase 8 执行步骤

1. 跑 `scripts/strip_meta_sections.py`：删除每个单元源文件从 `## 📋 自检清单` 到文件末尾的全部内容（含自检清单 + 版本记录）
2. 全局清理上表 8 类过程元数据
3. 替换"教师用书说…"为"本单元…"
4. 删除"新增/追加/v1 已覆盖"等版本相对性措辞
5. 删除"给人类教师读的""可追溯"等造书者口吻
6. **重跑 `scripts/merge_book.py`** 重新合并 BOOK.md

> **工程提醒**：Edit 工具经常匹配不了 HTML 注释，拆脚手架时用 Python 脚本批量处理，不要用 Edit 工具逐条改。

## Phase 9：交付质量门（6 项全绿才交付）

| 检查项 | 方法 | 判据 |
|---|---|---|
| ① 板块完整 | `grep -c "^## 🎬\|^## 🧭\|^## 📌\|^### 💬\|^## 🎯\|^## 🔗\|^## 📐" BOOK.md` | = 单元数 × 7 |
| ② 禁用词 | `grep "AI\|伴读\|指挥官\|prompt\|批量指挥\|对话框\|Socratopia\|让学生" BOOK.md` | = 0 |
| ③ 元数据残余 | `grep "自检清单\|版本记录\|<!-- v2\|教师用书说\|给人类教师读的\|v2.0 增量\|v1.0\|v1.1" BOOK.md` | = 0 |
| ④ 单元数 | `grep -c "^# Unit\|^# Starter" BOOK.md` | = 预期单元数 |
| ⑤ 锚点 | 检查 `merge_book.py` 输出 | 全部 ✓ |
| ⑥ 文件大小 | 合并后字节数 | 与预期相符（±10%） |

**任何一项不过，修完重跑。**

> 注：判据②的禁用词表和判据③的元数据关键词需按具体项目调整（不同项目平台术语不同）。
