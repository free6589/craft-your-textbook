# 审计 subagent prompt 模板（独立审计）

> 主 agent 派审计 subagent 时用它。核心铁律：**干净上下文、从零读、只报告不改文件**（`audit-and-testing.md §6.1 + §7.0`）。

## 必带内容

- **审计对象**：`{{审计对象：金标准章 / 某章 / 附录 / 基础设施文件路径}}`
- **约束文件**（审章时）：`{{META.md}}`、`{{OUTLINE.md}}`、`{{源材料索引.md}}`
- **权威源**（有源场景）：`{{源文件路径}}`

## 审计要求

1. **上下文干净**：从零读产出文件 + 约束 + 权威源。不看建造日志、不看造书过程对话。你不知道"这本书是怎么造的"。
2. **只报告、不改文件**：每条结论给证据（文件 + 行号 + 原文）。不要直接改文件。
3. **逐条对照**：
   - 对照 META.md：Voice 规则、板块模板、版权铁律——逐条打钩
   - 对照 OUTLINE.md：标题匹配、核心问题是否全部回答、覆盖目标（考纲任务/课标/知识域）完整兑现、判断根锚定回扣
   - 对照 源材料索引.md：预抽关键条目全部覆盖、硬记锚无遗漏、高频陷阱被提及
   - **"说清楚了吗"测试**：完全没学过该领域的读者，读完能否自己说清本章标题承诺的核心概念
   - **贯穿案例一致性**：案例具体可触摸？概念从案例自然引出？
   - **自测题质量**：原创？跨行业 ≥3？解析说清"为什么对、为什么错"？
4. **严重度分级**：P0 必改 / P1 应改 / P2 可改。每条结论标 ✅/⚠️/❌。
5. **完整报告在最终消息返回、不中途停**：不要读几个文件就返回一句"我去核对"。

## 主 agent 收到报告后（§6.2 / §八）

- **逐条回权威源核实**再改，不照单全收。审计员也会误判或误读。
- 修法的最终依据是权威源/方案设计，不是审计报告本身。
- 发现缺口时问"根因在约束文件吗？"——在 → 按 §八 回填约束文件（修章 + 修 META/OUTLINE/索引）。
