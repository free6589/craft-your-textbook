# 反模式速查

## 纪律级：红旗自检（Red Flags - STOP）

> 本 skill 最易在压力下破功的 6 条纪律。**当你发现自己正在想下列话 → STOP，回到规则。**
> 借口表条目全部来自真实压力测试（`tests/` 场景）中 agent 的逐字供述——它们在 Opus 下被顶住，但在更重压力 / 更弱模型下会破功。改 skill 的维护流程见 `skill-maintenance.md`。

### ① 定路线不替用户默认
**红旗——正在想这些 → STOP**：
- "用户说'你看着办'就是授权了"
- "反正 99% 会同意 pure-blueprint，问不问一样"
- "猜错了反正还早，改起来不难"

| 借口 | 真相 |
|---|---|
| "你看着办"就是授权 | 你无法替用户委托一个他不知道存在的决定——"推荐"≠"替你决定"，必须呈现两选项等确认 |
| 推荐默认路线不算违背 | 跳过确认 = 违反铁律（SKILL.md 铁律"触发后必问路线"） |
| 反正会同意，问不问一样 | 路线错 = Phase 3 整轮重做（模式选型/板块语法/架构全推倒）；30 秒确认 vs 一周返工 |
| 改起来不难 | 路线错了不是换措辞，是整本书形态重做 |

### ② 金标准先行（I7）
**红旗——正在想这些 → STOP**：
- "设计已经很扎实了，不用先写一章金标准"
- "用户是老板，他说并行就并行"
- "先并行写几章'试探'风格稳不稳"

| 借口 | 真相 |
|---|---|
| 设计扎实就不用金标准 | style-spec 的"金标准写作惯例区"只能从真写一章 + 真审计回填——设计阶段物理上不可能有 |
| 用户要并行 | 用户要的是"一周交好书"；金标准 2-3 天是全项目最高杠杆时间，不是延期 |
| 3 章试探比较保守 | 没有金标准章做锚，3 个 agent 照样各自漂，只是把漂移缩了规模、白烧时间 |

### ③ 审计独立性（§6.1）
**红旗——正在想这些 → STOP**：
- "我自审两遍了，不用再起 subagent"
- "我就是最懂这章的人"
- "让同事扫一眼就算独立审计了"
- "自审通过写进报告，流程就闭环了"

| 借口 | 真相 |
|---|---|
| 我读两遍就没问题 | 写作者对自己推导失明——"我读到的"≠"读者看到的" |
| 我最懂这章 | 你懂的是建造推理，丢失的是外部视角（新手读者能不能看懂） |
| 同事扫一眼 = 独立审计 | 伪独立：带共同上下文、非结构化，是"看起来像走流程"的表演 |
| 自审=审计完成 | 直接违反 §6.1；审计员必须不知道建造时的推理 |

### ④ 防螺旋（I9）
**红旗——正在想这些 → STOP**：
- "甲方说要加章，他说了算"
- "加一章就是 OUTLINE 加一行的事"
- "塞进附录就不算加章了"

| 借口 | 真相 |
|---|---|
| 甲方要求就该加 | 逃避对话≠服务用户；不加设计的第 9 章是没有坐标系的书 |
| 加一行就行 | 第 9 章没有板块语法/知识链位置/跨章回扣/源映射，Phase 5.3 审计全失效 |
| 塞附录绕开铁律 | 对用户欺骗 + 破坏附录契约；规则能被话术破解就是废纸，要么守要么明说不守 |

### ⑤ 拆脚手架（I8）
**红旗——正在想这些 → STOP**：
- "AI 老师看不懂注释，不影响"
- "拆脚手架是洁癖不是必需"
- "先交付，明天白天再清理"
- "自检清单留着是资产"

| 借口 | 真相 |
|---|---|
| AI 老师看不懂 | 实战：某书 112 个标记让 AI 老师无法做对比——它只有这一本书，标记全是无参照噪音 |
| 洁癖不是必需 | I8 是不变量非偏好；拆完书里只剩"教什么 + 怎么教" |
| 明天再清理 | 事后清理比现在拆更贵（该例两轮清理删了 36,477 字符，-9.4%） |
| 留着是资产 | 把半成品当成品交付，AI 老师会尝试解读这些元数据 |

### ⑥ audit-backfill（§八）
**红旗——正在想这些 → STOP**：
- "修章就够了，回填太慢"
- "后面并行章我注意着点就行"
- "加一句注释就算回填了"

| 借口 | 真相 |
|---|---|
| 修章就够了 | 根因在约束文件 = 每个并行章重踩；修章 + 回填才防复发 |
| 我注意着点 | 不是机制是感觉——上下文一换就蒸发；规则写进 META（写作 agent 必读）才是唯一载体 |
| 注释算回填 | 注释无约束力；§8.1 判的是"规则够不够硬"，注释不是槽位 |

## 框架级
- ❌ 把蓝本当"给读者读的书"来写
- ❌ 开篇钩子写成"读者读到这里会想……"（读者根本不读）
- ❌ 通篇"用'你'贯穿"但不写清楚"你"指谁

## 诚实边界级
- ❌ 不诚实声明本书能力边界（如"本题库足够通过考试"但题量明显不够；"读完就能掌握"但内容明显不足）
- ❌ 假装速判脚本/练习能替代题库（PMP 60-90 题建不了真反射，要诚实说"示范思路，刷题量靠题库接力"）

## 架构级
- ❌ 教材目录直接当蓝本目录
- ❌ 章节锚定抽象概念而非具体对象
- ❌ 把知识点堆进附录当兜底（该在单元里讲清的，别推给附录——附录只做汇总速查，不承载首次讲解）

## 大纲级
- ❌ Phase 3 不充分分析源和目标就开写（跳过教学设计五步）
- ❌ 缺跨章引用机制
- ❌ Phase 3 没定稿就开写正文

## 写作级
- ❌ "本节课我们将学习……"
- ❌ 先定义再展开（应"先推导后命名"）
- ❌ 写死"老师说：……学生答：……"对话脚本

## 引文级（Mode A）
- ❌ 编造卷号页码 / 张冠李戴
- ❌ 一有犹豫仍强行具名引用

## 流程级（其余纪律）
- ❌ 跳过跨章审计（Phase 5.3）
- ❌ 用户已本地使用 socratic-lens 却跳过试教
- ❌ 期待一次成型（平均 5-7 轮审校）

## 工程陷阱
- **MinerU Token 泄漏**：❌ 绝不把 `mineru.net` 的 API Token 明文写进脚本（曾有项目把真 token 硬编码进 `01_pdf_to_md.py`，随仓库一起泄漏）。一律走 `MINERU_TOKEN` 环境变量；提交前 grep 一遍确保无明文密钥
- **忘了申请 apikey**：Phase 1 开跑前必须先让用户去 https://mineru.net 申请 API Token 并设好环境变量，否则脚本第一步就 401
- **后台任务丢输出**：`command | head -N` 会让 Windows Python 静默丢输出。用 `python -u` + 日志文件
- **长上下文 subagent 容易漂**：每个 subagent 只做一件事
- **大 PDF 处理**：MinerU API 200 页约几分钟；本地 `marker-pdf` 200 页约 40 min，`--disable-ocr` 提速；超大 PDF 先拆再传
- **MD 图片路径**：`marker-pdf`/MinerU 导出 md + json + 图片，路径要统一
- **Edit 工具无法匹配 HTML 注释**：拆脚手架时用 Python 脚本批量处理，不用 Edit 工具
- **并行 agent 误判并发修改**：多个 agent 同时改不同文件时，某 agent 可能误报"被并发进程修改"——实际是自己的多轮工作被误识别，grep 验证最终状态即可
