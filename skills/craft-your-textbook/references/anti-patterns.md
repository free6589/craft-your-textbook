# 反模式速查

## 框架级
- ❌ 把蓝本当"给读者读的书"来写
- ❌ 开篇钩子写成"读者读到这里会想……"（读者根本不读）
- ❌ 通篇"用'你'贯穿"但不写清楚"你"指谁

## 诚实边界级
- ❌ 不诚实声明本书能力边界（如"本题库足够通过考试"但题量明显不够；"读完就能掌握"但内容明显不足）
- ❌ 假装速判脚本/练习能替代题库（PMP 60-90 题建不了真反射，要诚实说"示范思路，刷题量靠题库接力"）

## 拆脚手架级（最易犯）
- ❌ 最终产物留 `<!-- v2 新增 -->` 等版本标记
- ❌ 书里写"本单元新增了 X"（AI 老师没有旧版对比）
- ❌ 保留自检清单（造书者 QA 打勾，非教学内容）
- ❌ 保留版本记录（v1.0/v1.1 修订日志，非教学内容）
- ❌ "教师用书说……"直接暴露来源（应转成"本单元……"）
- ❌ "给人类教师读的"口吻残留（应转成"给 AI 老师的指令"）
- ❌ 附录里留"v2.0 增量"段落

## 架构级
- ❌ 教材目录直接当蓝本目录
- ❌ 章节锚定抽象概念而非具体对象
- ❌ 把知识点堆进附录当兜底（该在单元里讲清的，别推给附录——附录只做汇总速查，不承载首次讲解）

## 大纲级
- ❌ Phase 3 不充分分析源和目标就开写（跳过教学设计五步）
- ❌ 缺跨章引用机制
- ❌ Phase 3 没定稿就开写正文

## 写作级
- ❌ "本节课我们将学习……"
- ❌ 先定义再展开（应"先推导后命名"）
- ❌ 写死"老师说：……学生答：……"对话脚本

## 引文级（Mode A）
- ❌ 编造卷号页码 / 张冠李戴
- ❌ 一有犹豫仍强行具名引用

## 流程级
- ❌ 让写作 agent 审计自己
- ❌ 无金标准节就并行写多节
- ❌ 跳过跨章审计（Phase 5.3）
- ❌ 跳过 L5 教学测试
- ❌ 期待一次成型
- ❌ 跳过拆脚手架 + 质量门（Phase 6）

## 工程陷阱
- **MinerU Token 泄漏**：❌ 绝不把 `mineru.net` 的 API Token 明文写进脚本（曾有项目把真 token 硬编码进 `01_pdf_to_md.py`，随仓库一起泄漏）。一律走 `MINERU_TOKEN` 环境变量；提交前 grep 一遍确保无明文密钥
- **忘了申请 apikey**：Phase 1 开跑前必须先让用户去 https://mineru.net 申请 API Token 并设好环境变量，否则脚本第一步就 401
- **后台任务丢输出**：`command | head -N` 会让 Windows Python 静默丢输出。用 `python -u` + 日志文件
- **长上下文 subagent 容易漂**：每个 subagent 只做一件事
- **大 PDF 处理**：MinerU API 200 页约几分钟；本地 `marker-pdf` 200 页约 40 min，`--disable-ocr` 提速；超大 PDF 先拆再传
- **MD 图片路径**：`marker-pdf`/MinerU 导出 md + json + 图片，路径要统一
- **Edit 工具无法匹配 HTML 注释**：拆脚手架时用 Python 脚本批量处理，不用 Edit 工具
- **并行 agent 误判并发修改**：多个 agent 同时改不同文件时，某 agent 可能误报"被并发进程修改"——实际是自己的多轮工作被误识别，grep 验证最终状态即可
