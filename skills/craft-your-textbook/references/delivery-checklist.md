# 拆脚手架 + 交付质量门

> **这是最关键、也最容易被跳过的一步**。实战教训：某本书的初版留了 112 个 `<!-- v2 新增 -->` 标记 + 8 个自检清单 + 8 个版本记录，审计后发现"AI 老师没法做对比"，两轮清理共删除 36,477 字符（-9.4%）。**这不是可选项，是交付前的硬门。**

> **⚠️ 本文所有 grep 命令的统一前提（Phase 7 与 Phase 9 都适用）**：Git Bash 下先 `export LC_ALL=C.UTF-8`，否则含中文/emoji 的匹配在 C locale 下按字节匹配会误判；或改用 `rg` / python 更稳。
>
> **脚本说明**：下文提到的 `strip_meta_sections.py` / `merge_book.py` 都指**你项目里那份副本**（从 skill 复制来、已按本书改过的，约定在 `<项目根>/scripts/`），不是 skill 目录里的原件。

## 三个收尾阶段的分工（先理清 7 / 8 / 9）

造书末尾有三个阶段，别混淆：

| Phase | 在什么上做 | 做什么 | 时机 |
|---|---|---|---|
| **7 终检** | **单元源文件**（volume-1-units/*.md、appendix/*.md） | 内容层扫查，趁还没合并、好定位好改 | 合并 BOOK.md **之前** |
| **8 拆脚手架** | 单元源文件 | 删除造书过程元数据，然后重跑合并 | 终检通过后 |
| **9 质量门** | **合并后的 BOOK.md** | 交付前最后 6 项硬门 | 交付前 |

> Phase 7 和 9 有意重叠（禁用词、板块等两处都查）——7 是在源文件上早发现早改，9 是在最终产物 BOOK.md 上的交付卡关。7 查得越干净，9 越可能一次全绿。

## Phase 7 终检清单（合并前，在单元源文件上跑）

逐项跑，有问题就地改：

| 检查项 | 命令（在项目根跑） | 判据 |
|---|---|---|
| 禁用词 | `grep -rn "AI\|伴读\|指挥官\|prompt\|批量指挥\|对话框\|Socratopia\|让学生" volume-1-units/ appendix/` | 0（"AI 老师"是合法的，人工确认） |
| 乱码 U+FFFD | `grep -rn $'�' volume-1-units/ appendix/`（UTF-8 locale 下；或 `rg "\x{FFFD}"`） | 0（MinerU OCR 残留的替换字符全部改掉） |
| 板块齐全 | 每个单元 6 个二级板块（`## 🎬🧭📌🎯🔗📐`）+ 1 个嵌在 📌 下的三级板块（`### 💬`），合称 7 板块，都在 | 齐全 |
| 跨单元引用 | 每处"Unit X"指向真实存在的单元 | 无空指 |
| 坑型编号 | 每单元 📐 里 P1/P2/… 不重复、不跳号 | 一致 |

终检通过 → 进入 Phase 8 拆脚手架。

## 为什么必须拆（Phase 8）

**造书过程产生的所有元数据，对 AI 老师零价值。**

AI 老师只读最终这一本书。它没有 v1、没有"教师用书"、没有别的参照——所以书里任何"对比参照""修订日志""质检清单"都是噪音。

**口诀：拆完脚手架，书里只剩"教什么 + 怎么教"，没有"怎么造的"。**

## 必须拆除的 8 类过程元数据

| 类别 | 示例 | 为什么拆 |
|---|---|---|
| ① 版本标记注释 | `<!-- v2 师生合版新增 -->` | AI 老师看不到"v1"，标记无对照意义 |
| ② "新增内容"措辞 | "本单元新增了 X""v2 追加 Y" | AI 老师没有"旧版"可对比 |
| ③ 自检清单 | `- [x] 🎬 场景具体（…）` | 这是造书者的 QA 打勾，不是教学内容 |
| ④ 版本记录 | `v1.0（初稿）：完成 7 板块…` | 修订日志是作者维护笔记 |
| ⑤ 源教材引用 | "教师用书说…""教材原文指出…" | 转成"本单元…"直接陈述，不暴露来源 |
| ⑥ 造书者口吻 | "给人类教师读的""可追溯" | 转成"给 AI 老师的指令"语气 |
| ⑦ 增量描述 | "v2.0 增量""在 v1 基础上追加" | 删掉版本相对性，只留绝对内容 |
| ⑧ 过程勾选项 | 自检清单里的 `- [x]` 打勾项 | 全删 |

## Phase 8 执行步骤

> **运行前提**：同 Phase 7/9——确保 UTF-8 locale（`export LC_ALL=C.UTF-8`），含中文/emoji 的匹配在 C locale 下可能误判。下文 grep 均需在项目根目录执行。

**1. 跑脚本删除板块级元数据（对应上表 ③④⑧）**

```bash
python scripts/strip_meta_sections.py volume-1-units/
```

删除每个单元源文件从 `## 📋 自检清单` 到文件末尾的全部内容（含自检清单 + 版本记录 + 过程勾选项）。这三类脚本一次性解决。

**2. 逐类搜索并清理行内元数据（对应上表 ①②⑤⑥⑦）**

搜索范围：**`volume-1-units/` 和 `appendix/`**——附录同样会残留过程元数据，不可漏查。每类先跑 grep 确认命中位置，再用 Python 脚本批量替换（**不要用 Edit 工具逐条改——HTML 注释经常匹配失败**）。每次替换后重跑 grep 确认归零。

| 类别 | 搜索命令 | 处理方式 |
|------|---------|---------|
| ① 版本标记注释 | `grep -rn '<!--\|-->' volume-1-units/ appendix/` | 整行删除含 `<!-- v` 或 `<!--v` 的 HTML 注释行 |
| ② "新增"措辞 | `grep -rn '新增\|追加\|新加\|v[0-9] 追加' volume-1-units/ appendix/` | 删掉版本相对性措辞，只保留绝对内容（如"本单元新增了 X"→ 删掉"新增了"，直接写 X） |
| ⑤ 源教材引用 | `grep -rn '教师用书说\|教材原文指出\|学生用书说\|原文指出' volume-1-units/ appendix/` | 转成"本单元…"直接陈述，不暴露来源 |
| ⑥ 造书者口吻 | `grep -rn '给人类教师\|可追溯\|造书者\|人类教师' volume-1-units/ appendix/` | 转成给 AI 老师的指令语气，或直接删除 |
| ⑦ 增量描述 | `grep -rn 'v[0-9]\.[0-9] 增量\|v[0-9] 基础\|在 v[0-9]\|基础上追加\|基础上补充' volume-1-units/ appendix/` | 删掉版本相对性，只留绝对内容 |

全部归零后，再跑一轮综合兜底扫描确认无遗漏：
```bash
grep -rn 'v[0-9]\|<!--\|教师用书\|新增\|增量\|人类教师\|可追溯\|造书者' volume-1-units/ appendix/ | grep -v 'AI 老师' | grep -v 'unit-0'
```

**3. 重跑合并**

```bash
python scripts/merge_book.py
```

## Phase 9：交付质量门（6 项全绿才交付）

> **运行前提**：见本文开头的 grep 统一前提（UTF-8 locale）。含中文/emoji 的匹配在 C locale 下按字节匹配可能误判。

| 检查项 | 方法 | 判据 |
|---|---|---|
| ① 板块完整 | `grep -c "^## 🎬\|^## 🧭\|^## 📌\|^### 💬\|^## 🎯\|^## 🔗\|^## 📐" BOOK.md` | = **单元数 × 7**（单元数含 Starter，每单元 6 个二级板块 + 1 个 `### 💬` 三级板块；**前提：附录不用这 7 个 emoji 作标题**，见 outline **第八节**约束） |
| ② 禁用词 | `grep -n "伴读\|指挥官\|prompt\|批量指挥\|对话框\|Socratopia\|让学生" BOOK.md`；"AI"单独查：`grep -on "AI[^ 老]" BOOK.md`（注意 `[^ 老]` 里含一个空格——`AI` 后紧跟空格的"AI 老师"不命中，只揪出后接其他字符的可疑 AI）后**人工确认** | = 0（"AI 老师"合法，人工放行） |
| ③ 元数据残余 | `grep "自检清单\|版本记录\|<!-- v2\|教师用书说\|给人类教师读的\|v2.0 增量\|v1.0\|v1.1" BOOK.md` | = 0 |
| ④ 单元数 | `grep -c "^# Unit\|^# Starter" BOOK.md` | = 预期单元数 |
| ⑤ 锚点 | 检查 `merge_book.py` 输出 | 全部 ✓ |
| ⑥ 文件大小 | 合并后字节数 | **首本书**：记录本次字节数作为 baseline，人工目测无异常缺章即可；**重跑时**：与上次 baseline 相比 ±10% |

**任何一项不过，修完重跑。**

> 注：判据②的禁用词表和判据③的元数据关键词需按具体项目调整（不同项目平台术语不同）。gate② 的"AI"检测靠人工放行"AI 老师"——因为它是全书合法高频词，任何自动排除都可能漏检行尾/换行处的 AI，人工过一遍最稳。
